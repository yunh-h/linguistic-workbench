# 歷史紀錄失敗與競爭情境回歸

本輪僅新增測試，沒有修改功能程式。涵蓋前次 SQLite 驗收尚未直接測試的組合情境。

## 新增案例

- 真實 SQLite 連線持有 `BEGIN IMMEDIATE` 寫入鎖：另一個 API 保存請求等候後回傳可重試的 503，不洩漏資料庫路徑，不留下空句子或半筆快照；鎖定期間可讀舊資料、驗證目前分析。解鎖後保存成功，再次重試不重複。
- HTTP 保存確實提交成功，再由瀏覽器攔截器丟棄回應：畫面保留分析並提供重試；第一次 API 回應為 201、重試為 200，句子與版本數皆維持一筆。
- 21 筆舊紀錄分三批匯入：第二批尚未提交就斷線，以及第二批已提交但回應遺失，各自測試。已提交版本保留、原 localStorage 字串不變、失敗時不提供清除原件；重試後恰有 21 個不同 analysis_id，沒有重複版本。
- 搜尋與語言條件快速切換，故意讓舊回應晚到且忽略取消訊號：畫面仍維持最新結果。
- 切換舊快照後立即重開最新版本：晚到的舊快照不取代最新版本。讀取法文版本清單時切到日文：晚到的法文清單不污染日文版本選單。
- 另一個瀏覽器 context 刪除紀錄後，原頁面點選尚未更新的項目：顯示找不到、保留輸入、允許重新分析；重新整理清單後移除項目，不自動呼叫 parser 或 LLM。
